How it works

Verification lives in code, not in the model
  1. Send. The driver sends a photo or PDF on WhatsApp. An unknown number gets "not registered"; a driver who has not consented gets the consent request, and nothing is stored.
  2. Store. The original goes to S3 in Mumbai with KMS encryption, under the cab and month. Medical certificates go to a restricted prefix and are never read by the model.
  3. Find. For a photo, SAM 3.1 finds the paper in the frame; code crops to it and straightens the text lines. The segmentation model only finds; if it fails, the original photo is read and the failure is logged.
  4. Read. The worker sends the clean page to the model with a strict JSON schema: document type, vehicle number, date, odometer, GSTIN, work done, advisories, a one-line summary, and how sure it is.
  5. Check. Plain rules decide: wrong vehicle, future date, no GSTIN, duplicate file or invoice, bank-name bill, partial proof, expired paper, odometer going backwards. Workshop advisories on tyres, brakes, clutch, steering, suspension or fuel open a safety action until a later bill shows the fix.
  6. Reply and train. The driver gets the result in English, Hindi or Telugu within seconds, with the exact problem when there is one, and a link to a short module in their language.
